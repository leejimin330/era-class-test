# 나라·계급·시대 테스트 (가제) — 기획서 & 개발 명세

> 이 문서는 기획서이자 Claude Code 작업 지시서다. 구현 시 "6. 개발 명세" 이후를 우선 참고하고, 판단이 애매하면 "2. 핵심 원칙"을 따른다.

---

## 1. 한 줄 컨셉

버튼 한 번으로 **"내가 인류 역사 어딘가에 태어났다면 어느 시대·어느 나라·어떤 계급이었을까"**를 실제 인구·계급 비율에 따라 뽑아주고, 그 삶을 TRPG 캐릭터 시트처럼 보여주는 유머형 역사 테스트 웹.

- 범위: **고대 페르시아부터 200년 뒤 네오 재팬(2226년)까지**
- 대부분은 농민으로 태어난다는 "현실"이 핵심 웃음 포인트이고, 왕·귀족은 극악 확률의 레어 결과가 된다.
- 기존 "다시 태어날 나라 시뮬(전생환생)"과 비슷한 계열이지만 **별도 도메인의 독립 사이트**다. 추후 AI 웹 플랫폼 입점 및 공용 재화 연동을 고려해 설계한다.

## 2. 핵심 원칙

1. **문항 없음.** 사용자는 아무것도 입력하지 않고 "태어나기" 버튼만 누른다.
2. **AI 실시간 생성 없음.** 모든 결과는 미리 구축한 **고정 데이터셋**에서 조합한다. 런타임 API 비용 0원.
3. **통계 기반 확률.** 시대 → 나라 → 계급 순으로 실제(추정) 인구 비율에 따라 가중 추첨한다.
4. **유머 80 + 역사 20.** 웃기되 틀린 역사는 쓰지 않는다. 각 결과에 짧은 실제 역사 팁 1개를 넣는다.
5. **결과는 시드로 재현 가능.** 같은 시드 + 같은 데이터셋 버전 = 같은 결과. 공유 링크는 결과 전체가 아니라 시드만 저장한다.

## 3. 사용자 흐름

```
랜딩 → [태어나기] 클릭 → 주사위/운명 판정 연출(2~3초)
     → 결과 화면(기본 결과 + 캐릭터 시트 + 공유 카드)
     → [다시 태어나기] (무료 횟수 차감 or 크레딧)
     → [상세 결과 보기] (크레딧)
     → [공유하기] (이미지 저장 / 링크 복사 / 카카오톡)
```

공유 링크로 들어온 사람은 친구의 결과를 보고 바로 "나도 태어나보기" 버튼으로 이어진다.

## 4. 결과 구성

### 4.1 기본 결과 (무료)

| 항목 | 예시 |
|---|---|
| 시대 | 기원전 500년경 |
| 나라 | 아케메네스 페르시아 |
| 계급 | 농민 (확률 71.3%) |
| 레어도 | ★ 커먼 |
| 직업 | 보리 농사 + 왕의 도로 건설 부역 |
| 기대 수명 | 34세 (판정 결과 반영) |
| 대표 식사 | 보리빵, 대추야자, 운 좋으면 양젖 |
| 하루 요약 | 한두 문장 |
| 캐릭터 시트 | 체력·지력·매력·운 능력치 |
| 역사 팁 | 짧은 실제 역사 사실 1개 |

### 4.2 상세 결과 (크레딧)

- **하루 일과 전체 묘사**: 시간대별(새벽/오전/오후/밤) 서술
- **TRPG 이벤트 로그**: 인생 중 발생한 판정 3~5개 (예: "역병 저항 판정 d20 → 4, 실패. 수명 −8")
- **인생 결말**: 사망 원인 또는 엔딩 문구
- 가족 구성, 재산, 세금, 취미 등 보조 디테일

### 4.3 공유 카드

- 세로형 1080×1920 (인스타 스토리) + 가로형 1200×630 (OG 이미지)
- 카드 구성: 시대·나라·계급, 레어도 별, 확률, 한 줄 드립, 캐릭터 시트 미니 레이더, 사이트 URL
- 레어도별 카드 테두리 색 차별화 (커먼 회색 → 레전더리 금색)

## 5. TRPG 요소 설계

### 5.1 캐릭터 시트

- 능력치 4종: **체력 / 지력 / 매력 / 운** (각 1~20)
- 계급별 능력치 기본값 범위를 데이터셋에 정의하고, 그 안에서 랜덤 결정
  - 예: 귀족은 지력 기본값이 높고, 농민은 체력이 높음

### 5.2 운명 판정 (d20)

- 결과 생성 시 d20 판정을 여러 번 굴려 이벤트를 결정한다.
- 판정 = d20 + 관련 능력치 보정 ≥ 시대·계급별 난이도(DC)
- 판정 결과가 수명, 신분 변동, 엔딩에 영향을 준다.
- **크리티컬(20)**: 신분 상승 이벤트 (예: 농민 → 하급 관리로 출세)
- **펌블(1)**: 처참한 이벤트 (단, 유머 톤 유지)

### 5.3 레어도

최종 확률 P(시대) × P(나라|시대) × P(계급|나라) 로 등급을 매긴다.

| 등급 | 조건(초안) | 예 |
|---|---|---|
| ★ 커먼 | P ≥ 1% | 대부분의 농민 |
| ★★ 언커먼 | 0.1% ≤ P < 1% | 상인, 장인 |
| ★★★ 레어 | 0.01% ≤ P < 0.1% | 하급 귀족, 승려 |
| ★★★★ 에픽 | 0.001% ≤ P < 0.01% | 고위 귀족 |
| ★★★★★ 레전더리 | P < 0.001% | 왕, 황제 |

임계값은 데이터셋 완성 후 실제 분포를 보고 조정한다.

## 6. 확률 모델

```
1단계: 시대 추첨      — eras[].weight 기준
2단계: 나라 추첨      — 해당 시대 polities[].populationShare 기준
3단계: 계급 추첨      — 해당 나라 classes[].share 기준
4단계: 직업/식사/일과 — 계급 내 후보 리스트에서 균등 추첨
5단계: 능력치·판정    — 시드 기반 난수
```

**시대 가중치 방식** (설정값으로 전환 가능하게 구현)

- `population`: 해당 시대 추정 출생자 수 비례 (가장 현실적, 근현대 비중이 커짐)
- `flattened`: 출생자 수에 지수 k(기본 0.5)를 적용해 완화 → **기본값으로 사용**
- `uniform`: 모든 시대 동일 확률

미래 시대(네오 재팬 등)는 실제 통계가 없으므로 **가상의 인구·계급 비율**을 설정하고 결과 화면에 "가상 시대" 뱃지를 붙인다.

## 7. 데이터셋

### 7.1 MVP 시대 목록 (초안, 10~12개)

1. 고대 이집트 (기원전 1300년경)
2. 아케메네스 페르시아 (기원전 500년경)
3. 로마 제국 (2세기)
4. 한(漢) (1세기)
5. 중세 유럽 (13세기)
6. 고려 (12세기)
7. 아즈텍 제국 (15세기)
8. 조선 (18세기)
9. 에도 일본 (18세기)
10. 산업혁명기 영국 (19세기)
11. 현대 (21세기)
12. 네오 재팬 (2226년, 가상)

시대당 나라 3~5개, 나라당 계급 4~6개를 목표로 한다. 한 시대에 데이터가 부족한 나라는 "기타 지역"으로 묶는다.

### 7.2 스키마 (TypeScript)

```ts
type Era = {
  id: string;               // "achaemenid-500bce"
  name: string;             // "아케메네스 페르시아 시대"
  yearLabel: string;        // "기원전 500년경"
  estimatedBirths: number;  // 시대 가중치 계산용
  fictional?: boolean;      // 미래 시대 등
  polities: Polity[];
};

type Polity = {
  id: string;
  name: string;
  populationShare: number;  // 해당 시대 내 비율 (합 1.0)
  classes: SocialClass[];
};

type SocialClass = {
  id: string;
  name: string;                 // "농민"
  share: number;                // 해당 나라 내 비율 (합 1.0)
  lifespan: [number, number];   // 기대 수명 범위
  statBase: Record<Stat, [number, number]>;
  jobs: string[];
  meals: string[];
  daySummaries: string[];       // 기본 결과용 한두 문장
  dayDetail: DayDetail[];       // 상세 결과용 시간대별 묘사
  events: EventRef[];           // 발생 가능한 판정 이벤트
  jokes: string[];              // 카드용 한 줄 드립
  historyTips: string[];        // 실제 역사 사실
  sources?: string[];           // 통계 출처 메모
};

type Stat = "body" | "mind" | "charm" | "luck";

type LifeEvent = {
  id: string;
  title: string;          // "역병 유행"
  stat: Stat;
  dc: number;
  success: EventOutcome;
  failure: EventOutcome;
  critical?: EventOutcome;
  fumble?: EventOutcome;
};

type EventOutcome = {
  text: string;
  lifespanDelta?: number;
  classChangeTo?: string;  // 신분 변동
  ending?: string;
};
```

- 데이터는 `data/eras/*.json`으로 시대별 파일 분리
- 이벤트는 `data/events/*.json`에 공용 풀로 두고 계급에서 id로 참조
- `data/version.json`에 데이터셋 버전 기록 (시드 재현용)
- 빌드 시 각 단계 비율 합이 1.0인지 검증하는 스크립트 실행

### 7.3 데이터 작성 가이드

- 비율은 학계 추정치 기반, 불확실하면 범위의 중간값 사용하고 `sources`에 메모
- 노예·불가촉 계급 등 민감한 계급은 **존재 자체는 반영**하되, 피해자를 조롱하는 농담은 금지. 유머는 시스템·상황·사소한 일상 쪽으로 돌린다.
- 특정 현존 민족·종교를 비하하는 표현 금지
- 현대 시대는 실제 국가별 인구·소득 분위로 계급을 대체 (예: "하위 20% 소득층")

## 8. 과금

- **무료 3회** (계정 기준), 이후 크레딧으로 재시도
- **상세 결과**는 결과 1건당 크레딧으로 해금 (무료 결과에도 적용 가능)
- 가격은 설정 파일로 분리: `REROLL_COST`, `DETAIL_COST`
- 크레딧은 추후 AI 웹 플랫폼 공용 재화로 이관할 수 있도록 지갑 로직을 별도 모듈로 분리
- 결제 연동(토스페이먼츠 등)은 MVP 이후. MVP에서는 관리자 수동 충전으로 테스트
- 유료 재화 판매 전 약관·환불 규정 정비 필수

## 9. 기술 스택

기존 플랫폼 기획과 동일하게 간다.

- **Next.js (App Router) + TypeScript**
- **Vercel** 배포, 공유 카드는 `next/og`(ImageResponse)로 생성
- **Supabase**: Auth(카카오·구글 로그인), Postgres(지갑, 결과 기록)
- Tailwind CSS
- 난수: 시드 기반 PRNG(mulberry32 등) 직접 구현, `Math.random` 사용 금지

## 10. 개발 명세 (Claude Code용)

### 10.1 폴더 구조

```
/app
  /page.tsx                 랜딩
  /roll/page.tsx            판정 연출 + 결과
  /r/[id]/page.tsx          공유 결과 페이지 (OG 메타 포함)
  /api/roll/route.ts        추첨 (서버에서만 실행)
  /api/detail/route.ts      상세 결과 해금
  /api/og/[id]/route.tsx    공유 카드 이미지
/lib
  /rng.ts                   시드 PRNG
  /roll.ts                  추첨 엔진 (순수 함수)
  /trpg.ts                  능력치·판정 로직
  /rarity.ts
  /wallet.ts                무료 횟수·크레딧 차감
/data
  /eras/*.json
  /events/*.json
  /version.json
/scripts
  /validate-data.ts         비율 합·참조 무결성 검사
/components
  ResultCard, CharacterSheet, DiceAnimation, EventLog, ShareButtons
```

### 10.2 DB 테이블 (Supabase)

```sql
wallets   (user_id pk, free_rolls_left int default 3, credits int default 0)
rolls     (id pk, user_id, seed text, data_version text,
           detail_unlocked bool default false, created_at)
credit_tx (id pk, user_id, delta int, reason text, created_at)
```

- 차감은 Postgres 함수(RPC)로 트랜잭션 처리해 동시 요청 시 중복 차감 방지
- RLS: 본인 지갑·기록만 조회 가능, `rolls`는 공유 페이지용으로 id 기반 공개 조회 허용(시드·결과만)

### 10.3 추첨 엔진 요구사항

- `roll(seed: string, data: Dataset, config: RollConfig): RollResult` — 순수 함수, 부작용 없음
- 같은 입력 → 항상 같은 출력 (단위 테스트로 보장)
- 추첨은 반드시 서버 라우트에서 실행. 클라이언트는 결과만 받는다.
- 공유 페이지는 DB의 seed + data_version으로 결과를 재계산해 렌더링

### 10.4 구현 순서

1. 데이터 스키마 + 샘플 시대 2개(페르시아, 조선) 작성 + 검증 스크립트
2. `rng.ts`, `roll.ts`, `trpg.ts`, `rarity.ts` + 단위 테스트
3. 비로그인 상태로 동작하는 결과 화면 (지갑 없이)
4. Supabase Auth + 지갑 + 무료 3회 차감
5. 공유 페이지 `/r/[id]` + OG 카드
6. 상세 결과 해금
7. 판정 연출 애니메이션, 레어도별 카드 디자인
8. 나머지 시대 데이터 채우기
9. 로그·분석 (레어도 분포, 공유율, 재시도율)

### 10.5 완료 기준

- 10만 회 시뮬레이션 시 계급 분포가 데이터셋 비율과 ±1% 이내
- 같은 시드로 공유 페이지 진입 시 원본 결과와 완전히 일치
- 무료 3회 소진 후 크레딧 없으면 재시도 불가, 동시 요청에도 중복 차감 없음
- 모바일(375px)에서 결과 화면과 카드가 깨지지 않음
- 공유 링크를 카카오톡에 붙였을 때 OG 이미지 정상 노출

## 11. 미결정 사항

- 서비스명 / 도메인
- 비로그인 사용자에게 체험 1회를 줄지 여부
- 크레딧 가격, 재시도·상세 해금 각각의 비용
- 시대 가중치 기본 모드(`flattened`의 k값) 최종 결정
- 네오 재팬 외 미래 시대 추가 여부
- 기존 전생환생 사이트와 계정·크레딧 공유 여부
